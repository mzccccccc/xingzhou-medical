# 记忆: 已办事项.md 的约定

## 位置与分栏(前端、后端分开保存)
- 后端: `docx/plan/backend/已办事项.md`
- 前端: `docx/plan/frontend/已办事项.md`(可能尚未创建, 不存在则跳过)
- 前端、后端**各自独立维护**, 不混写在同一文件。

## 编号规则
- 每个文件内条目编号**连续累加**(1, 2, 3, …), 跨多次更新**不重置**。

## 更新时间标注
- 每次更新, **把"更新时间"写在这次更新内容的前面**。
- 因此文件会随时间累积多个"日期 + 该日期完成事项"的段落;
  越靠后 / 日期越新的, 就是越近完成的事项。

## 现有格式参考(backend/已办事项.md)
- 顶部: `> 更新日期: YYYY-MM-DD`
- 条目: `### N. 标题` + 说明列表
- 判断"最新完成事项"时, 以**最近的更新日期 + 最大的连续编号**为准。

## 我(Claude)如何使用
- 每次提交前读取这两个文件, 定位最近一次更新所对应的条目,
  据此精炼写出 commit message(详见「Git 提交工作流」记忆)。
